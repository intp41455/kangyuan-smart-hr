## 📌 TL;DR（执行摘要）

- **核心结论**：针对康源集团考勤管理与薪酬核算中人工依赖度高（月耗7-10天）、流程碎片化（3次数据断裂）、标准不统一（70+版本考勤表）、易出错（错误率5%）四大核心痛点，设计了一套五层架构的智慧化人资系统平台。系统将403条验证规则编码为77条可执行规则引擎逻辑，通过钉钉API自动采集数据、规则引擎自动判定、薪酬引擎自动计算，实现月初1日自动启动→10日自动输出工资单的全闭环，人工干预率从95%降至5%以下。
- **关键行动**：分5阶段推进（6-12个月），第1-2月完成403条规则标准化编码，第2-4月开发系统MVP，第4-5月并行验证，第5-6月试点运行，第6-12月全集团推广。HR牵头、IT技术实施、行政/财务/法务全面协助。
- **合规提醒**：所有自动化逻辑须可追溯、可解释，每条计算结果附规则ID+版本号+制度条款依据；个税自动化计算的法律效力与审计要求需法务确认；社保公积金代缴（上海博曜部分人员）的跨区域规则需单独配置。

## 第一部分：系统整体架构设计

### 1.1 五层架构总览

系统采用五层分离架构，每层职责清晰、接口标准化，支持独立升级和横向扩展：

| 层次 | 名称 | 核心职责 | 技术实现 | 替代的人工操作 |
|------|------|----------|----------|----------------|
| L1 | 数据源层 | 多源数据自动采集 | 钉钉OpenAPI + 定时任务 | 人工导出Excel |
| L2 | 数据处理层 | 清洗、去重、融合、校验 | ETL Pipeline + 数据质量引擎 | 人工逐行核对 |
| L3 | 规则引擎层 | 考勤/薪酬/社保/个税规则判定 | JSON Schema规则定义 + DSL执行引擎 | 人工查制度、套公式 |
| L4 | 自动计算层 | 考勤汇总、工资计算、社保核算 | 规则引擎驱动批量计算 | 人工填Excel 35列公式 |
| L5 | 输出看板层 | 报表生成、看板展示、预警通知 | BI看板 + 钉钉机器人 + 审计日志 | 人工制作报表、微信群催收 |

### 1.2 架构设计原则

| 原则 | 说明 | 具体措施 |
|------|------|----------|
| 规则与代码分离 | 制度变更时改配置不改代码 | 规则以JSON Schema存储，可视化界面配置 |
| 全链路可追溯 | 每条计算结果可追溯到规则和数据源 | 审计日志记录：规则ID + 版本 + 输入 + 判定 + 结果 + 依据 |
| 异常分级处理 | 不是所有异常都需要人工 | 三级分类：自动处理 / 需确认 / 人工介入 |
| 数据单一源头 | 避免多版本数据不一致 | 钉钉API为唯一数据源，系统内生成唯一考勤汇总表 |
| 渐进式推广 | 降低变革风险 | 5阶段实施：梳理→开发→验证→试点→推广 |

### 1.3 与现有系统的集成关系

**数据完整性校验规则**：

| 校验项 | 规则 | 异常处理 |
|--------|------|----------|
| 人员覆盖 | 钉钉人员数 = 花名册人员数 | 差异→通知HR核查 |
| 日期完整性 | 打卡记录覆盖当月所有工作日 | 缺失→标记缺卡 |
| 审批单匹配 | 每张审批单的日期范围内是否有对应打卡/考勤记录 | 不匹配→标记异常 |
| 排班覆盖 | 每位员工每个工作日有排班记录 | 缺失→使用默认班次 |
| 重复数据 | 同一员工同一时间点仅一条打卡 | 重复→取最早一条 |

#### 2.1.3 智能核对引擎规则

**打卡完整性核对**：

```
规则 R-ATT-001: 每日打卡完整性校验
IF (排班类型 == "工作日") THEN:
    IF (上班打卡时间 IS NULL OR 下班打卡时间 IS NULL) THEN:
        IF (存在已审批的请假单覆盖该日期) THEN:
            标记为"请假" → 自动处理
        ELSE IF (存在已审批的补卡单) THEN:
            标记为"补卡" → 自动处理
        ELSE:
            标记为"缺卡" → 人工介入
```

**迟到判定规则（4级梯度）**：

```
规则 R-ATT-008: 迟到4级梯度判定
INPUT: 实际上班打卡时间, 标准上班时间
DIFF = 实际打卡时间 - 标准上班时间（分钟）

IF DIFF <= 0: 正常
ELSE IF DIFF <= 5:  迟到1级 → 扣款10元
ELSE IF DIFF <= 15: 迟到2级 → 扣款30元
ELSE IF DIFF <= 30: 迟到3级 → 扣款50元
ELSE:               迟到4级 → 按旷工半天处理

依据: §考勤及休假管理 第三节第二条第(三)款
版本: v2024.06
```

**补卡规则**：

```
规则 R-ATT-015: 补卡机制
INPUT: 员工ID, 月份
月度补卡次数 = COUNT(该员工当月已审批补卡单)

IF 月度补卡次数 <= 3:
    补卡有效，不扣款
ELSE:
    超出次数 × 10元/次 → 扣款

注意: 迟到/早退/旷工不得使用补卡抵消
依据: §考勤及休假管理 第三节第二条第(二)款
```

**全勤奖判定规则**：

```
规则 R-ATT-020: 全勤奖判定
INPUT: 员工ID, 月份, 入职日期, 离职日期

IF (入职当月 OR 离职当月) AND (实际出勤天数 < 应出勤天数):
    全勤 = "否"（新入职如果当月能达到实际月应出勤天数，按全勤核算）
ELSE:
    IF (病假天数 == 0 AND 事假天数 == 0 AND 旷工天数 == 0
        AND 异动缺勤天数 == 0 AND 迟到早退次数 == 0
        AND 补卡次数 <= 3):
        全勤 = "是" → 奖励100元
    ELSE:
        全勤 = "否" → 奖励0元

依据: §考勤及休假管理 第三节第二条第(一)款
```

**加班费计算规则**：

```
规则 R-ATT-022: 加班费计算
INPUT: 加班类型, 加班时长, 日工资
日工资 = 合计工资标准 / 21.75
小时工资 = 日工资 / 8

IF 加班类型 == "工作日加班":
    加班费 = 小时工资 × 加班小时 × 1.5
ELSE IF 加班类型 == "休息日加班":
    IF 存在调休安排:
        不计加班费，计入存休
    ELSE:
        加班费 = 小时工资 × 加班小时 × 2.0
ELSE IF 加班类型 == "法定节假日加班":
    加班费 = 小时工资 × 加班小时 × 3.0

依据: §考勤及休假管理 第三节第四条
注意: 周末加班起止时间内含于钉钉考勤结果文本中
      需正则提取: r"加班(\d{2}-\d{2})\s(\d{2}:\d{2})到(\d{2}-\d{2})\s(\d{2}:\d{2})\s*(\d+)小时"
```

**护理岗三班倒核对规则**：

```
规则 R-ATT-005: 护理岗跨日班次核对
INPUT: 员工岗位, 班次类型, 打卡日期

IF 岗位 IN ["介护师", "护士", "护理员"]:
    IF 班次 == "A班":
        标准上班 = 08:00, 标准下班 = 16:00, 日期归属 = 当日
    ELSE IF 班次 == "P班":
        标准上班 = 16:00, 标准下班 = 24:00, 日期归属 = 当日
    ELSE IF 班次 == "N班":
        标准上班 = 00:00, 标准下班 = 08:00, 日期归属 = 前一日
        // N班跨午夜，打卡日期可能为次日，需特殊处理
        IF 打卡日期 == 班次日期 + 1 AND 打卡时间 BETWEEN 00:00 AND 08:00:
            日期归属 = 班次日期（前一日）

依据: §考勤及休假管理 第一节第一条 + 钉钉考勤组配置
```

### 2.2 模块二：薪酬核算自动化

#### 2.2.1 功能架构

| 子模块 | 功能 | 替代的人工操作 | 自动化率 |
|--------|------|----------------|----------|
| 考勤-工资联动 | 考勤汇总表自动传入薪酬计算Pipeline | 人工VLOOKUP关联考勤表和工资表 | 100% |
| 11步自动计算 | 35列工资表全自动化计算 | 人工填公式、手动录入数据 | 95% |
| 多维度校验 | 交叉校验+波动检测+合规校验 | 人工抽查（覆盖率<20%） | 100% |
| 薪资明细生成 | 生成"有理有据"的工资明细单 | 人工制作工资条 | 100% |
| 银行代发文件 | 自动生成银行代发格式文件 | 人工整理代发清单 | 100% |

#### 2.2.2 薪酬计算Pipeline（11步公式链）

**输入**：考勤汇总表（34列） + 人员花名册 + 工龄表 + 社保缴费表 + 绩效表 + 交通补贴表

| 步骤 | 计算项 | 公式（系统编码） | 数据依赖 | 规则ID |
|------|--------|-----------------|----------|--------|
| 1 | 合计工资标准(E) | E = 基本工资(C) + 绩效工资标准(D) | 合同约定 | R-SAL-001 |
| 2 | 当月绩效工资(F) | F = D × (1 + 3 × (绩效分数-100)/100) | 绩效考核表 | R-SAL-002 |
| 3 | 实际应出勤工资(G) | G = C + F - ROUND(E/21.75 × 异动缺勤天数(L), 2) | 考勤表第32列 | R-SAL-003 |
| 4 | 病假扣款(M) | M = IFS(J≤7, E/21.75×J×20%, J≤15, E/21.75×J×50%, J>15, 最低工资/21.75×J×20%) | 考勤表第7列 | R-SAL-009 |
| 5 | 事假扣款(N) | N = ROUND(E/21.75 × K, 2) | 考勤表第8列 | R-SAL-010 |
| 6 | 迟到扣款(O) | O = 超过3次补卡次数 × 10 | 考勤表第29列 | R-SAL-011 |
| 7 | 扣款合计(Q) | Q = M + N + O + 其他扣款(P) | 步骤4-6+手动 | R-SAL-012 |
| 8 | 增加合计(V) | V = 工龄工资(R) + 交通补贴(S) + 其他津贴(T) + 全勤奖(U) | 工龄表+补贴表+考勤表 | R-SAL-013 |
| 9 | 应发工资(W) | W = ROUND(G - Q + V, 2) | 步骤3+7+8 | R-SAL-014 |
| 10 | 应纳税所得额(Z) | Z = W - 五险(X) - 公积金(Y) | 社保缴费表 | R-SAL-015 |
| 11 | 实发工资(AE) | AE = ROUND(Z - 个税(AC) + 个税调整(AD), 2) | 步骤10+个税计算 | R-SAL-016 |

**关键规则编码**：

**病假3级梯度扣款（R-SAL-009）**：

```json
{
  "rule_id": "R-SAL-009",
  "rule_name": "病假扣款3级梯度",
  "version": "v2024.06",
```

## ⚠️ 合规提醒 & 假设

### 合规提醒
1. **个税自动化计算**：系统自动计算个税的法律效力需法务确认，建议与税务局扣缴端数据交叉验证
2. **薪酬数据保密**：系统涉及全员薪酬数据，须符合《个人信息保护法》要求，权限严格分级
3. **考勤记录保存**：劳动法要求考勤记录保存2年以上，系统须满足数据留存合规要求
4. **社保跨区域代缴**：上海博曜部分人员社保在上海代缴，公积金在西安缴纳，需单独配置规则
5. **电子签批法律效力**：线上签批流程需符合《电子签名法》要求
6. **病假>15天计算规则**：2024版制度规定按最低工资80%计发，需确认当地最低工资标准更新机制
7. **橄榄枝协议违约金**：离职管理中的培训违约金和竞业限制条款需法务逐项确认

### 假设
1. 钉钉OpenAPI的调用频率和权限可满足308人×30天×4接口的日调用量
2. 集团网络环境可支撑系统稳定运行（99.9%可用性）
3. 各机构行政配合数据迁移和试点工作
4. 现有考勤管理制度在系统开发期间不发生重大变更
