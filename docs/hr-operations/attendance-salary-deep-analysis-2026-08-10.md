## 📌 TL;DR（执行摘要）

- **核心结论**：康源集团当前考勤与工资体系制度设计完善、Excel公式体系精密，但执行层面高度依赖人工在12个节点上手工操作，每月耗费7-10个工作日，涉及4家公司250+人、5种异构数据源、3次手工数据转换，错误风险高且无审计轨迹。本次分析已完整获取并交叉验证了**三大制度原文**（2022版考勤管理制度PDF + 2024版人力资源管理制度RAR包90+文件 + 12张2024版考勤制度截图），**两个钉钉群**169条消息（工资节点群52条+集团办公群117条），**微信文件目录**70+个考勤汇总表版本文件，**给肖肖交接**文件夹社保操作步骤，以及4类审批流程Excel（人资/考勤/行政/财务），首次实现了制度原文与执行实践的完整闭环验证。
- **关键行动**：以钉钉API为数据入口，构建"数据自动采集→AI智能解析→规则引擎计算→Agent编排协调→自动交付"的五层自动化架构，将12个人工节点压缩至1个例外审批节点，人工操作减少95%+；优先解决跨组织文件访问权限和考勤管理范围授权问题。2024版病假3级梯度计算规则已从制度原文验证并可直接编码为规则引擎。
- **合规提醒**：涉及薪酬数据、个税计算、社保公积金的自动化改造须确保规则引擎与现行法规一致；2024版考勤管理制度与2022版存在病假计算规则差异（已确认2024版为现行版本），橄榄枝协议违约金条款需法务确认。

## 1. 整体框架架构

### 1.1 五层架构总览

康源集团考勤与工资管理体系由五个层次构成（见上方架构图）：

| 层次 | 名称 | 核心内容 | 当前状态 |
|------|------|----------|----------|
| L1 | 制度层 | 考勤管理制度(康源发〔2024〕06号)、人力资源管理制度、绩效考核方案 | ✅ 制度完善 |

| L4 | 核算层 | 工资表35列公式体系：11步计算链从应出勤工资到实发工资 | ✅ 公式精密 |
| L5 | 交付层 | 4家公司独立工资表 + 社保公积金明细 + 公积金汇缴单 + 审批存档 | ⚠️ 多文件割裂 |

## 3. 工资计算体系底层逻辑

### 3.1 工资表结构（35列）

| 列号 | 列名 | 数据来源 | 计算方式 |
|------|------|----------|----------|
| A | 序号 | 自动 | =ROW()-3 |
| B | 姓名 | 手动/模板 | 直接输入 |
| C | 基本工资标准 | 手动/模板 | 合同约定 |
| D | 绩效工资标准 | 手动/模板 | 合同约定 |
| E | 合计工资标准 | 公式 | =C+D |
| F | 当月绩效工资 | 公式/手动 | =VLOOKUP(绩效表) 或 0(无绩效) |
| G | 实际应出勤工资 | 公式 | =C+F-ROUND(E/21.75*L,2) |
| H | 月应计薪天数 | 公式 | =VLOOKUP(考勤表,28列) |
| I | 实际计薪天数 | 公式 | =VLOOKUP(考勤表,29列) |
| J | 病假天数 | 公式 | =VLOOKUP(考勤表,4列) |
| K | 事假天数 | 公式 | =VLOOKUP(考勤表,5列) |
| L | 异动缺勤天数 | 公式 | =VLOOKUP(考勤表,6列) |
| M | 病假扣款 | 公式 | =IFS(J<=7,E/21.75*J*20%,J<=15,E/21.75*J*50%) |
| N | 事假扣款 | 公式 | =ROUND(E/21.75*K,2) |
| O | 迟到早退补卡扣款 | 公式 | =VLOOKUP(考勤表,33列)*10 |
| P | 其他扣款 | 手动 | 人工输入 |
| Q | 扣款合计 | 公式 | =SUM(M:P) |
| R | 工龄工资 | 手动 | 从工龄工资表录入 |
| S | 交通补贴 | 公式 | =VLOOKUP(交通补贴表) |
| T | 其他津贴 | 手动 | 人工输入 |
| U | 全勤奖励 | 公式 | =IF(考勤表全勤="是",100,0) |
| V | 增加合计 | 公式 | =SUM(R:U) |
| W | 应发工资 | 公式 | =ROUND(G-Q+V,2) |
| X | 五险 | 手动 | 从社保缴费明细表录入 |
| Y | 公积金 | 手动 | 从社保缴费明细表录入 |
| Z | 应纳税所得额 | 公式 | =W-X-Y |
| AA | 专项扣除税合计 | 手动 | 人工输入 |
| AB | 实际纳税所得额 | 公式 | =Z-AA |
| AC | 个税 | 手动 | 人工计算(累计预扣法) |
| AD | 个税调整 | 手动 | 人工输入 |
| AE | 实发工资 | 公式 | =ROUND(Z-AC+AD,2) |

### 3.2 核心计算公式详解

#### 3.2.1 实际应出勤工资 (G列)
```
G = C + F - ROUND(E / 21.75 * L, 2)
  = 基本工资 + 当月绩效 - ROUND(合计工资标准 / 21.75 * 异动缺勤天数, 2)
```
- **21.75** = 月计薪天数 = (365 - 104周休) / 12
- **日薪** = 合计工资标准 / 21.75
- 异动缺勤按日薪全额从应出勤工资中扣除

#### 3.2.2 病假扣款 (M列) — 梯度比例
```
M = IFS(
  J <= 7,  ROUND(E / 21.75 * J * 20%, 2),   // 病假≤7天：扣日薪的20%
  J <= 15, ROUND(E / 21.75 * J * 50%, 2)     // 病假8-15天：扣日薪的50%
)
```
- **设计逻辑**：短病假公司承担80%，长病假公司承担50%
- **潜在问题**：IFS函数只有两个条件，超过15天的病假扣款未定义（可能返回#N/A错误）

#### 3.2.3 事假扣款 (N列) — 全额扣除
```
N = ROUND(E / 21.75 * K, 2)
  = ROUND(合计工资标准 / 21.75 * 事假天数, 2)
```

#### 3.2.4 迟到早退补卡扣款 (O列)
```
O = VLOOKUP(B, 福祉考勤!B:AH, 33, FALSE) * 10
  = 考勤表"迟到早退补卡超过3次次数" × 10元
```
- **设计逻辑**：前3次补卡免费，超过3次后每次扣10元

#### 3.2.5 应发工资 (W列)
```
W = ROUND(G - Q + V, 2)
  = ROUND(实际应出勤工资 - 扣款合计 + 增加合计, 2)
  = ROUND((基本+绩效-异动扣) - (病假+事假+迟到+其他) + (工龄+交通+其他+全勤), 2)
```

#### 3.2.6 实发工资 (AE列)
```
AE = ROUND(Z - AC + AD, 2)
   = ROUND(应纳税所得额 - 个税 + 个税调整, 2)
   = ROUND((应发工资 - 五险 - 公积金) - 个税 + 个税调整, 2)
```

#### 3.2.7 绩效工资计算 (F列) — 季度考核月化
```
绩效应用结果 = ROUND(绩效工资标准 × 3 × (绩效分数 - 100) / 100, 2)
当月绩效工资 = 绩效工资标准 + 绩效应用结果
            = 绩效工资标准 × (1 + 3 × (绩效分数 - 100) / 100)
```

| 绩效分数 | 当月绩效工资 | 说明 |
|----------|-------------|------|
| 100 | 绩效工资标准 × 1 = 标准 | 基准 |
| 115 | 绩效工资标准 × 1.45 | 加45% |
| 150.53 | 绩效工资标准 × 2.5159 | 加151.59% |

- **"3"的含义**：季度3个月的绩效调整在当月一次性发放/扣除
- **绩效考核比例**：个人薪酬总额的10%（固定工资90% + 绩效工资10%）

## 5. AI自动化改造方案

### 5.1 改造目标

| 维度 | 当前 | 目标 |
|------|------|------|
| 人工操作节点 | 12个 | 1个(例外审批) |
| 月度耗时 | 7-10工作日 | 0.5工作日 |
| 数据转换次数 | 3次手工 | 0次(全自动) |
| 准确率 | ~95%(人工) | 99.9%+(规则引擎) |
| 审计轨迹 | 无 | 全链路可追溯 |
| 人资角色 | 数据搬运工 | 规则管理者+数据分析 |

### 5.2 五层自动化架构

#### Layer 1: 数据自动采集层

| 数据源 | 采集方式 | 替代的人工操作 |
|--------|----------|----------------|
| 钉钉打卡 | `dws attendance report query-data` API 定时拉取 | 人工导出月报 |
| 钉钉审批 | `dws oa +list-executed` API 自动抓取 | 人工下载审批PDF |
| 钉钉通讯录 | `dws contact` API 自动同步 | 人工维护人员信息 |
| 社保系统 | 社保平台API或RPA自动导出 | 人工导出社保明细 |
| 公积金系统 | 公积金平台API或RPA | 人工导出汇缴单 |

**技术实现**：
- 使用钉钉dws CLI的attendance API按月自动拉取全员考勤数据
- OA审批API自动获取已通过的审批单（课时费、交通补贴、绩效、居家办公等）
- 定时任务每月1日凌晨自动触发，数据写入统一数据湖

#### Layer 2: AI智能解析层

| 解析任务 | AI技术 | 替代的人工操作 |
|----------|--------|----------------|
| 打卡异常识别 | 规则引擎(缺卡/迟到/早退自动判定) | 人工逐天核对250+人 |
| 审批PDF提取 | OCR + NLP(从审批内容提取金额/人员/项目) | 人工阅读PDF提取信息 |
| 加班文本解析 | NLP正则+语义解析(从"休息,加班07-12..."提取天数/时长) | 人工解析考勤结果文本 |
| 存休自动结转 | 规则引擎(上月余额+本月加减) | 人工跨月追踪记忆 |
| 工龄自动计算 | 规则引擎(入职日期→司龄→金额，含调动规则) | 人工维护工龄表 |

**技术实现**：
- 打卡异常：基于钉钉API返回的结构化数据(出勤天数/迟到次数/缺卡次数)自动判定
- 审批PDF：dws oa API返回审批内容文本，用NLP提取关键信息(金额、人员、项目类型)
- 加班文本：正则表达式 + 语义解析从考勤结果文本中提取加班天数和时长
- 存休结转：数据库维护每人每月的存休余额，自动加减

#### Layer 3: 规则引擎层

| 引擎 | 输入 | 输出 | 核心规则 |
|------|------|------|----------|
| 考勤规则引擎 | 打卡数据+审批数据 | 考勤汇总表(34列) | 08:30-17:30作息、月休6/4天、全勤判定、补卡3次阈值 |
| 工资计算引擎 | 考勤汇总+工资标准+津贴 | 工资表(35列) | 21.75计薪、病假梯度(20%/50%)、事假全额、全勤100 |
| 个税计算引擎 | 应纳税所得额+累计数据 | 当月个税 | 累计预扣法、7级超额累进税率、速算扣除数 |
| 社保公积金引擎 | 缴费基数+比例 | 单位/个人缴纳额 | 养老16%/8%、医疗7%/2%、失业0.7%/0.3%、工伤0.32%、公积金5%/5% |
| 绩效计算引擎 | 季度绩效分数+绩效标准 | 当月绩效工资 | 绩效标准×(1+3×(分数-100)/100) |
| 工龄计算引擎 | 入职日期+调动记录 | 工龄工资 | 满1年100/满2年200...调动1-15日新公司算 |

**技术实现**：
- 将现有Excel公式全部翻译为代码规则，消除VLOOKUP列号硬编码问题
- 个税计算使用国家税务总局累计预扣法公式，自动维护年度累计数据
- 所有规则参数化配置，支持在线修改（如病假比例从20%调为15%只需改配置）

#### Layer 4: Agent编排层

| Agent | 职责 | 触发条件 |
|-------|------|----------|
| 考勤Agent | 按公司分派考勤数据、自动生成考勤汇总表 | 每月1日自动触发 |
| 工资Agent | 调用规则引擎计算工资、生成工资表 | 考勤Agent完成后触发 |
| 社保Agent | 拉取社保数据、计算五险一金、生成申报表 | 每月1日自动触发 |
| 审批Agent | 抓取审批单、提取金额、自动关联到工资表 | 实时监听新审批 |
| 异常预警Agent | 检测异常数据(如个税跳档、实发为负)并推送 | 计算完成后自动触发 |
| 调动处理Agent | 处理跨公司调动人员的工龄/社保迁移 | 检测到调动审批时触发 |

**技术实现**：
- 基于dws API构建Agent编排，每个Agent负责一个领域
- 异常预警Agent自动标记需人工介入的异常项，推送到钉钉群
- 人工只需处理被标记的异常项（预计<5%的数据量）

### 5.3 实施路径
